# 针对微信的 DPI 检测

在校园网多设备检测中，**针对微信的 DPI 深度包检测**常与 TTL 检测、UA 指纹检测配合使用。

## ❓ 微信 UID 的提取原理

微信 UID（unionid）是微信用户的统一标识。针对一个微信开放平台帐号下的应用，同一用户的 unionid 是唯一的。在校园网多设备检测中，微信 UID 的提取和统计是识别共享上网的重要手段。

### 微信流量的识别

DPI 设备首先通过以下特征识别微信流量：

| 特征类型 | 具体特征 | 说明 |
| --- | --- | --- |
| Host 字段 | `*.weixin.qq.com` | 微信 HTTP 请求中的域名特征 |
| 载荷特征码 | `0x00100001` | 微信数据包中相对固定的二进制指纹 |
| 端口特征 | 80 / 8080 / 443 | 微信通信常用端口 |
| TLS 头部 | `0x16 0x03 0x01` | 加密通道的 TLS 握手特征 |
| 业务标识 | 大类业务 id：1，小类业务 id：0009 | XDR 话单中标识即时通信-微信的 DPI 大小类业务 ID |

### UID 的提取

微信客户端在发送消息时，数据包中固定偏移位置存在一串相同的二进制数，这串二进制数对于同一微信客户端是唯一的。DPI 设备通过以下方式提取微信 UID：

1. **明文流量**：通过 DPI 规则库中的正则表达式，在 XDR 数据中抽取微信 ID 等字段，生成用户网络身份维表。具体输出字段可包括微信 ID、微信图片、微信视频等虚拟身份信息。
2. **加密流量**：微信采用 MMTLS 协议加密，DPI 设备无法直接解析载荷中的 UID，但可通过对 MMTLS 握手的元数据提取进行间接关联。

::: warning
微信 UID 提取的准确性受加密协议版本、DPI 特征库更新时间等因素影响。部分安全网关已支持对 MMTLS 流量的处理，但仍有局限性。
:::

## ❓ 多设备判断逻辑

以锐捷 UAC 的防共享机制为例，当某一个 IP 的报文中存在**多个微信 UID** 时，会将该 IP 识别为共享代理 IP。

| 场景 | 表现 | 判定 |
| --- | :---: | ---: |
| 单设备使用微信 | 同一 IP 下仅 1 个微信 UID | ✔️ 正常 |
| 多设备使用微信 | 同一 IP 下 ≥ 2 个微信 UID | 🚨 多设备 |
| 部分设备未使用微信 | 统计到的 UID 数量可能不足 | ⚠️ 需结合其他机制 |

::: tip 该检测机制存在局限性
如果多台设备均未使用微信，则无法通过微信 UID 识别，如果同一用户在单设备上登录多个微信账号，也可能被误判。因此通常需要结合多种检测手段综合判断。
:::

## 🛠️ 常见对抗手段

针对微信 DPI 检测，常见的对抗思路包括：

### 1. 加密代理转发

使用代理工具将微信流量通过加密隧道转发至外部节点，DPI 设备无法识别到微信特征码，从而无法统计 UID 数量。

### 2. User-Agent 伪装与 MMTLS 处理

使用 UA2F 等插件统一修改 HTTP 请求中的 User-Agent 字段，消除不同设备 UA 差异带来的检测风险。UA2F 提供了 `handle_mmtls` 选项用于控制是否处理微信 MMTLS 流量。

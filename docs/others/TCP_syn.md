# 🧬 TCP SYN 检测原理

在校园网多设备检测中，**TCP 指纹检测**常与 TTL 检测配合使用。TTL 工作在 IP 层，成本低；TCP 检测工作在传输层，通过三次握手暴露的协议栈特征，判断同一公网 IP 后是否存在多台设备。

## ❓ 什么是 TCP 指纹

TCP（Transmission Control Protocol）是面向连接的传输层协议。建立连接时，客户端发送 `SYN` 包，其中包含窗口、MSS、窗口扩大因子、SACK、时间戳等选项。不同操作系统 TCP/IP 协议栈实现不同，这些字段和选项顺序组合起来就是 **TCP 指纹**。

### 📃 常见操作系统的 TCP SYN 指纹示例

| 操作系统 | TTL | MSS | Window Size | WScale | SACK-Permitted | Timestamp | 选项顺序 |
| --- | :---: | :---: | :---: | :---: | :---: | :---: | ---: |
| Windows 10/11 | 128 | 1460 | 64240 | 8 | 允许 | 启用 | MSS,NOP,WScale,NOP,NOP,SACKOK,TS |
| Linux / Android | 64 | 1460 | 65535 / 29200 | 7/8 | 允许 | 启用 | MSS,SACKOK,TS,NOP,WScale |
| iOS / macOS | 64 | 1460 | 65535 | 8 | 允许 | 启用 | MSS,NOP,WScale,NOP,NOP,SACKOK,TS |
| 部分 Unix / 网络设备 | 255 | 1460 | 4128 / 其他 | 0/其他 | 视实现 | 视实现 | 随系统变化 |

::: warning 注意
上表为常见示例，实际值会随系统版本、补丁、MTU、VPN、代理、防火墙和用户配置变化。排查时应以实际抓包为准。
:::

## 🔬 校园网检测 TCP 的原理

校园网网关或 DPI 设备通常在出口处采集 TCP `SYN`、`SYN-ACK`、`ACK` 及后续数据包，提取 TCP 指纹并进行关联分析。

### 1. 正常直连（未挂载路由器）

单台设备直接连接校园网时，网关看到的 TCP 指纹稳定，且与已知操作系统匹配。

| 设备类型 | 请求流量类型 | 抓取的 TCP 特征 | 校园网网关判定 |
| --- | :---: | :---: | ---:|
| Windows 电脑 | TCP SYN | TTL=`128`，Win=`64240`，WScale=`8`，TS 启用 | ✔️ 唯一设备（Windows） |
| Android 手机 | TCP SYN | TTL=`64`，Win=`65535`，WScale=`8`，TS 启用 | ✔️ 唯一设备（Android/Linux） |
| iPhone | TCP SYN | TTL=`64`，Win=`65535`，WScale=`8`，TS 启用 | ✔️ 唯一设备（iOS） |

### 2. 挂载路由器（经过 NAT 转发）

路由器进行 NAT 转发时，通常会修改源 IP、源端口和校验和，但**一般不会修改 TCP 选项、窗口、MSS 和时间戳**。因此，多台设备共享同一公网 IP 时，TCP 指纹可能混合出现。

| 下挂设备组合 | 抓取的 TCP 特征 | 校园网网关判定 |
| --- | :---: | ---: |
| Windows 电脑 | TTL=`127`，TCP 指纹仍为 Windows，TSval 单调 | ⚠️ 配合其他探针持续跟踪 |
| Windows 电脑 + Android 手机 | 同一公网 IP 出现 TTL=`127`/`63`，Win=`64240`/`65535`，选项顺序不同，TSval 多序列 | 🚨 **封禁** |
| Windows 电脑 + iPhone | 同一公网 IP 出现 TTL=`127`/`63`，TCP 指纹 Windows 与 iOS 混合，TSval 交错 | 🚨 **封禁** |

### 3. TCP 时间戳检测

TCP 时间戳选项（Timestamps）包含 `TSval` 和 `TSecr`。正常情况下，同一设备的 `TSval` 会按自身时钟单调递增。NAT 后多台设备共用公网 IP 时，网关可能看到同一 IP 的 `TSval` 出现多个独立递增序列、跳变或回退。

| 场景 | TCP 时间戳表现 | 网关判定 |
| --- | :---: | ---: |
| 单设备直连 | `TSval` 单调、连续 | ✔️ 正常 |
| 单设备经路由器 | `TSval` 仍单调，但 TTL 递减 | ⚠️ 配合其他探针持续跟踪 |
| 多设备经路由器 | 同一公网 IP 下 `TSval` 交错、跳变、多序列 | ⚠️ 配合其他探针持续跟踪 |

::: info
部分系统会禁用 TCP 时间戳，部分 NAT/防火墙会剥离时间戳，因此时间戳检测通常需要与 TTL、窗口、MSS、选项顺序等特征联合判断。
:::

## 🛠️ 路由器/NAT 对 TCP 字段的影响

| 字段 | NAT 是否修改 | 说明 |
| --- | :---: | ---: |
| 源 IP | 是 | 改为路由器 WAN 口公网 IP |
| 源端口 | 是 | 端口复用与转换 |
| IP 校验和 | 是 | 重算 |
| TCP 校验和 | 是 | 重算 |
| TCP 选项 | 通常否 | 除非特殊防火墙剥离时间戳/SACK |
| TCP 窗口 | 通常否 | 端到端字段，NAT 一般不改 |
| MSS | 通常否 | 但可能被 `TCPMSS clamp` 修改 |
| TCP 时间戳 | 通常否 | 部分安全网关会清除 |
| TTL | 是 | 三层转发每跳 `-1`，见 TTL 文档 |

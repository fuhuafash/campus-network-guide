# 🧬 TCP SYN 检测

在校园网多设备检测中，**TCP 指纹检测**常与 TTL 检测配合使用。TCP 检测工作在传输层，通过三次握手暴露的协议栈特征，判断同一公网 IP 后是否存在多台设备。

## ❓ 什么是 TCP 指纹

TCP（Transmission Control Protocol）是面向连接的传输层协议。建立连接时，客户端发送 `SYN` 包，其中包含 `Window Size` 、MSS、WScale、SACK、 `Timestamps` 等选项。不同操作系统 TCP/IP 协议栈实现不同，这些字段和选项顺序组合起来就是 **TCP 指纹**。

## ❓ 初始窗口（Window Size）

客户端 `SYN` 包中的初始窗口由操作系统协议栈决定，不同系统默认值不同：

| 系统 | 典型初始窗口 |
| --- | :---: |
| Windows 10/11 | 64240 |
| Linux / Android | 65535 / 29200 |
| iOS / macOS | 65535 |

单设备直连时，网关看到的是一个稳定的窗口值，挂路由器后，若同一公网 IP 交替出现 `64240` 和 `65535`，即说明后面至少有一台 Windows 和一台类 Unix 设备。

::: warning
窗口值会随系统版本、MTU、代理、防火墙等变化，应以实际抓包为准。
:::

## ❓ TCP 时间戳（Timestamps）

`SYN` 包中的时间戳选项包含 `TSval`（发送方时钟）和 `TSecr`（回显对方时钟）。同一设备的 `TSval` 会按自身时钟单调递增，因此：

| 场景 | 表现 | 判定 |
| --- | :---: | ---: |
| 单设备直连 | `TSval` 单调、连续 | ✔️ 正常 |
| 单设备经路由器 | 仍单调，TTL 递减 | ⚠️ 持续跟踪 |
| 多设备经路由器 | 同一公网 IP 下 `TSval` 交错、跳变、多序列 | 🚨 多设备 |

部分系统会禁用时间戳，部分防火墙会剥离该选项，因此时间戳通常与初始窗口、TTL、MSS、选项顺序联合判断。

## 🛠️ NAT 对 TCP 字段的影响

| 字段 | NAT 是否修改 | 说明 |
| --- | :---: | ---: |
| 源 IP / 源端口 | 是 | 改为公网 IP 并复用端口 |
| IP / TCP 校验和 | 是 | 重算 |
| TCP 初始窗口 | 通常否 | 端到端字段 |
| TCP 时间戳 | 通常否 | 部分安全网关会清除 |
| MSS | 通常否 | 可能被 `TCPMSS clamp` 修改 |
| TTL | 是 | 每跳 `-1` |

# 🔗 TCP 连接数检测

TCP 连接数检测比 TTL 更贴近“行为规模”，是校园网多设备检测中较难规避的维度。网关不看设备数，只看同一账号 / 公网 IP 下的并发会话数、新建速率等。

## ❓ 基本概念
TCP 连接由五元组标识：源 IP、源端口、目的 IP、目的端口、协议。

NAT 后所有设备共享同一公网 IP，网关看到的是所有设备会话数之和。路由器下挂多台设备时，NAT 会把它们的内网连接统一映射到同一个公网 IP，但每条连接仍各自占用一条 conntrack 条目，大量短连接（网页、API、视频分片）会使其快速堆积，从而进一步推高连接数。


## 🔬 检测原理
网关在出口维护 NAT 会话表，按账号 / IP 统计。

挂路由器后，所有下挂设备会话数叠加，表现为：

- 并发连接总数明显升高

- 每秒新建连接数（CPS）升高

- 目的 IP 离散度、目的端口分布变广

- DNS 查询数增加

- TIME_WAIT 数量增多

- NAT 端口复用明显

当校园网检测设备发现同一账号或IP下`并发连接 / CPS`过高时触发限制

::: tip 关于常见阈值？
并发超过 100 / 200 / 500 / 1000，或 CPS 超过 50 / 100 / 200 时。  
不同学校规则不同，以实际为准。
:::


## 📃 常见检测指标

| 指标 | 说明 | 多设备共享时表现 |
| --- | :---: | ---: |
| 并发连接总数 | 当前 conntrack 中该公网 IP 的会话数 | 明显高于单设备 |
| 每秒新建连接数 CPS | 单位时间新建会话数 | 多设备同时请求时升高 |
| 目的 IP 离散度 | 不同目的 IP 数量 | 多设备访问不同服务时升高 |
| 目的端口分布 | 端口种类与数量 | 游戏、P2P、视频等混合 |
| DNS 查询数 | 同一公网 IP 的 DNS 请求 | 多设备各自解析，数量增加 |
| TIME_WAIT 数量 | 短连接关闭后残留 | 大量网页 / API 请求后升高 |
| 每源端口映射数 | NAT 端口复用情况 | 同一公网 IP 映射大量内网端口 |

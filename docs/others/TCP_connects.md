# 🔗 TCP 连接数检测

在校园网多设备检测中，**TCP 连接数检测**是比 TTL 更贴近“行为规模”的手段。TTL 看单个数据包的跳数，连接数看同一账号 / 公网 IP 下同时存在多少条会话。目前较无应对方案。

## ❓ 什么是 TCP 连接数

TCP 连接数通常指 NAT 网关连接跟踪表（conntrack）中，与某个内网主机或公网 IP 关联的 TCP 会话条目数量。

一条 TCP 连接由五元组唯一标识：

| 字段 | 说明 |
| --- | ---: |
| 源 IP | 发起方 IP |
| 源端口 | 发起方端口 |
| 目的 IP | 目标服务器 IP |
| 目的端口 | 目标服务端口，如 80、443 |
| 协议 | TCP / UDP 等 |

::: info
校园网网关看到的不是“设备数”，而是“会话数”。多设备共享时，所有设备会话都映射到同一公网 IP，网关统计该公网 IP 的并发连接数、新建速率等。
:::

### 📃 常见 TCP 连接状态

| 状态 | 含义 | 是否占用 conntrack |
| --- | :---: | ---: |
| SYN_SENT | 已发 SYN，等待响应 | 是 |
| SYN_RECV | 收到 SYN，等待 ACK | 是 |
| ESTABLISHED | 连接已建立 | 是 |
| FIN_WAIT / TIME_WAIT | 关闭中 / 等待超时 | 是，直到超时 |
| CLOSE_WAIT | 被动关闭等待 | 是 |
| CLOSED | 已关闭 | 超时后删除 |

## 🔬 校园网检测 TCP 连接数的原理

校园网网关在出口处维护 NAT 会话表，并对每个账号 / 公网 IP 进行统计。

### 1. 正常直连（未挂载路由器）

单台设备直接连接校园网时，会话数通常处于单设备合理范围。

| 设备类型 | 典型行为 | 并发 TCP 连接数参考 | 校园网网关判定 |
| --- | :---: | :---: | ---: |
| Windows 电脑 | 待机 / 浏览网页 | 10 ~ 80 | ✔️ 正常单设备 |
| Android 手机 | 待机 / 刷视频 | 10 ~ 100 | ✔️ 正常单设备 |
| Windows 电脑 | 流媒体 | 50 ~ 200 | ✔️ 正常单设备 |
| Windows 电脑 | BT / P2P下载 | 200 ~ 1000+ | 🚨 可能触发限速 |

::: tip
阈值因学校、运营商、时段而异。常见策略：并发连接数超过 `100 / 200 / 500 / 1000`，或每秒新建连接数超过 `50 / 100 / 200`，触发限制。
:::

### 2. 挂载路由器（经过 NAT 转发）

路由器后所有设备共享同一公网 IP，网关看到的是**所有设备会话数之和**。

| 下挂设备组合 | 并发连接数特征 | 校园网网关判定 |
| --- | :---: | ---: |
| Windows 电脑 | 单设备会话数，TTL 可能为 127 | 🚨 **封禁** |
| Windows 电脑 + Android 手机 | 会话数明显叠加，目的 IP / 端口分散 | ⚠️ 配合其他探针持续跟踪 |
| 电脑 + 手机 + PAD | 并发连接数、新建速率、DNS 查询数上升 | ⚠️ 配合其他探针持续跟踪 |
| 多设备同时 BT / 视频 / 游戏 | 连接数短时间内暴涨，TIME_WAIT 增多 | ⚠️ 配合其他探针持续跟踪 |

### 3. 常见检测指标

| 指标 | 说明 | 多设备共享时表现 |
| --- | :---: | ---: |
| 并发连接总数 | 当前 conntrack 中该公网 IP 的会话数 | 明显高于单设备 |
| 每秒新建连接数 CPS | 单位时间新建会话数 | 多设备同时请求时升高 |
| 目的 IP 离散度 | 不同目的 IP 数量 | 多设备访问不同服务时升高 |
| 目的端口分布 | 端口种类与数量 | 游戏、P2P、视频等混合 |
| DNS 查询数 | 同一公网 IP 的 DNS 请求 | 多设备各自解析，数量增加 |
| TIME_WAIT 数量 | 短连接关闭后残留 | 大量网页 / API 请求后升高 |
| 每源端口映射数 | NAT 端口复用情况 | 同一公网 IP 映射大量内网端口 |

## 🛠️ 路由器 / NAT 对连接数的影响

| 项目 | 说明 |
| --- | ---: |
| NAT 会话表 | 每条连接占一条 conntrack，路由器需维护 |
| 端口复用 | 多设备通过不同源端口映射到同一公网 IP |
| 超时时间 | `TIME_WAIT`、`ESTABLISHED` 超时越长，表项占用越久 |
| 连接跟踪上限 | 路由器 `nf_conntrack_max` 过小会导致丢包、断流 |
| 流量卸载 | Flow Offload 可提升转发性能，但不减少网关侧统计 |
| 代理 / VPN | 可能把多设备流量集中到少数连接，也可能增加新连接 |

## 🔍 排查方法

 查看当前连接数
   ```bash
   cat /proc/sys/net/netfilter/nf_conntrack_count
   cat /proc/sys/net/netfilter/nf_conntrack_max
   ```

 查看连接跟踪表
   ```bash
   conntrack -C
   conntrack -L | head
   conntrack -L -p tcp | wc -l
   ```

 在客户端查看本机连接
   ```bash
   ss -s
   ss -tan | wc -l
   netstat -an | grep ESTABLISHED | wc -l
   ```

 观察短时间新建连接
   ```bash
   watch -n 1 'cat /proc/sys/net/netfilter/nf_conntrack_count'
   ```

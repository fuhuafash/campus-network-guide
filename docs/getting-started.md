# 🚀 快速开始

本指南将准备工作拆解为以下三个核心板块

## 🛠️ 硬件与系统要求

由于防检测手段通常需要对数据包进行实时修改（如修改 TTL、重写 HTTP 头、做包过滤甚至流量加密），这给路由器的 CPU 和内存带来了一定压力。盲目使用低端路由器会导致频繁重启、断网或网速变慢。

### 📋 推荐配置清单

| 项目 | 最低/推荐要求 | 选型说明与原因 |
| :--- | :--- | :--- |
| **芯片 (SoC)** | MT7981B (Filogic 820) 或更高 | 强烈建议Soc性能水平在 MT7981B 及以上性能（如 MT7986、IPQ6000/6018、x86 等）。低性能芯片（如 MT7621）在处理复杂的防火墙规则和代理流量时容易 CPU 满载丢包 |
| **运行内存 (RAM)** | 256MB 及以上 | 修改 UA、运行防检测插件或代理客户端均需占用内存，实测运行UA3F和shellclash对于256MB机器刚好 |
| **系统固件** | OpenWrt 24.10 或更新版本 | 推荐使用 OpenWrt 24.10 |

::: info 
关于不同硬路由如何刷上`OpenWrt`，本指南暂不提供教学
:::

::: tip 购买/刷机建议
如果你尚未购买路由器，可以优先考虑基于 **MT7981B** 芯片的常见机型（如红米 AX3000T、移动 RAX3000M 等），这些机型社区生态丰富，容易刷入 OpenWrt 24.10。
:::


## 🌐 你可能需要准备代理节点

**为什么需要准备代理节点？**

新一代校园网检测多设备最核心的手段之一是**DPI 深度包检测**：
* 校园网提供商常常有能力通过机器学习检测对应应用流量，即使应用已经通过TLS加密，例如检测微信
* 校园网检测设备往往是动态多重检测，即使通过了传统检测，检测设备也会通过定期DPI抽检对应应用流量
* 使用加密隧道后，校园网检测设备只能看到一条通往代理节点的加密数据流，**无法窥探内部具体的 UA 信息和应用特征**，从而天然免疫大部分 HTTP 层的多设备检测

::: danger 注意事项
部分高校可能会严抓“翻墙”行为，请在事先了解学校政策，若不了解相关代理技术，务必放弃使用
:::


## 🎯 了解学校检测手段与常见组合

校园网厂商（锐捷、Dr.COM、雨滴等）会使用对应的探针，来组合成所谓的防代理方案，且往往是动态多重检测，并非依靠单一的条件来判断，目的是为了减少误封杀的概率，为了接下来配置防检测的准备，务必了解检测组合。


### 🔍 常见的“检测组合”与验证方法

#### TTL + UA <Badge type="warning" text="大部分高校" />
数据包经过路由器后 TTL 会少 1，同时抓取未加密的 HTTP 流量，若同一 IP 在短时间内同时出现 Windows 和 iPhone 的 UA 签名，直接判定违规。

::: info 🧪 如何验证
单双设备对比：只连 1 台电脑上网 1 小时正常，再连 1 台手机同时上网，3~5 分钟内突然弹警告断网  
网页测试：手机与电脑同时访问任意 HTTP（http://example.com）网页，观察是否瞬间触发下线警告
:::


#### TTL + UA + DHCP 指纹 + MAC
即便通过手段隐藏了 UA，新设备连接 Wi-Fi 申请 IP 时，不同系统（iOS/Android/Windows）发送的 DHCP 指纹依然不同，再加上不同厂商MAC前缀不同，网关比对发现冲突即触发拦截。
::: info 🧪 如何验证
依旧被检测：在锁定了 TTL 并修改 UA 的情况下，依旧被强制下线  
无法中继Wi-Fi：通过路由器的中继Wi-Fi功能无法中继学校无线网络，或者中继后被检测
:::


#### TTL + TCP 时间戳 （ + NTP 时钟同步 ）
不同设备的系统开机时间和硬件时钟频率不同。多台设备经过 NAT 后，同一个 IP 发出的 TCP 时间戳（TSval）会剧烈跳变。
::: info 🧪 如何验证
同操作系统触发：在完成上述伪装的情况下，单台电脑看视频完全正常；但只要 2~3 台同操作系统电脑同时进行大量 TCP 连接（如网页浏览、游戏、下载），网关抓取到时间戳跳变，就会频繁触发强制下线
:::


#### 应用层 DPI 流量分析 <Badge type="warning" text="大部分高校" />
使用 DPI 分析应用流量特征。
::: info 🧪 如何验证
特定 App 触发：浏览网页没问题，但手机一打开微信接收消息或启动特定应用，网络立刻被切断
:::

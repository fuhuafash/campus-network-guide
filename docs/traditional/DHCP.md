# 🏷️ DHCP 指纹检测原理

**DHCP 指纹检测**属于应用层与网络配置协议层的终端指纹识别技术，无需解密 HTTPS 流量即可精准识别终端操作系统类型。  

## ❓ 什么是 DHCP 指纹

DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）用于为局域网内的终端设备动态分配 IP 地址及网络参数。在客户端向 DHCP 服务器发送请求时，会在报文中附带多个配置选项（Options）。

::: info
不同操作系统在实现 DHCP 客户端时，请求的 Option 编号顺序（Option 55）、厂商标识（Option 60）以及客户端标识（Option 61）存在固定的行为习惯，这些选项组合构成了独一无二的“DHCP 指纹”。
:::

### 📑 常见操作系统的 DHCP 指纹特征

校园网 DHCP 服务器或探针根据请求报文中的 Option 特征判断客户端类型：

| 操作系统类型 | Option 55 请求参数序列 (Prl) | Option 60 厂商标识特征 (Vendor Class ID) |
| :--- | :--- | :--- |
| **Windows 10/11** | `1, 3, 6, 15, 31, 33, 43, 44, 46, 47, 119, 121, 249, 252, 114` | `MSFT 5.0` |
| **现代 Android** | `1, 3, 6, 15, 26, 28, 51, 58, 59, 43, 114, 108` | `android-dhcp-<版本号>` |
| **现代 iOS** | `1, 121, 3, 6, 15, 108, 114, 119, 252` | 通常为空 |
| **现代 macOS** | `1, 3, 6, 15, 108, 114, 119` | 通常为空 |
| **现代发行版Linux / BusyBox OpenWrt** | `1, 3, 6, 12, 15, 28, 51, 58` / `1, 3, 6, 15, 28, 51, 12` | 通常为空 / `udhcp <版本号>` |


## 🔬 校园网检测 DHCP 指纹的原理

校园网 DHCP 服务器或出口网关通过对 UDP 67/68 端口的 `DHCP Request` 报文进行抓包与解析，提取指纹并与系统基准库比对。

### 1. 正常直连（未挂载路由器）

单台终端直接连接校园网发起 DHCP 地址请求时，DHCP 指纹与后续网络流量的协议栈特征保持一致。

| 设备类型 | 请求流量类型 | 抓取的 DHCP 指纹 | 校园网网关判定 |
| :--- | :--- | :--- | :--- |
| **Windows 电脑** | DHCP Request | `Option 55` 含 249/252/114，`Option 60` 为 `MSFT 5.0` | 唯一设备（Windows） |
| **Android 手机** | DHCP Request | `Option 55` 含 26/28/58/59，`Option 60` 含 `android` | 唯一设备（Android） |


### 2. 挂载路由器（经过路由 NAT 转发）

宿舍接入路由器后，路由器 WAN 口向校园网请求 IP 地址，此时发出的是路由器自身系统的 DHCP 指纹；而下挂设备流量经 NAT 转发后访问外网，网关会对比 DHCP 记录与实际流量特征。

| 场景与设备组合 | 抓取的网络特征组合 | 校园网网关判定 |
| :--- | :--- | :--- |
| **OpenWrt 路由器 WAN 口申请 IP** | DHCP 指纹为 `Linux/udhcpc` | ⚠️ **识别为路由器设备** |
| **路由 WAN 口 + 下挂 Windows** | DHCP 指纹为 `Linux/udhcpc`，而上报 HTTP UA 为 `Windows NT 10.0` | ⚠️ **协议栈指纹冲突，判定挂载路由** |

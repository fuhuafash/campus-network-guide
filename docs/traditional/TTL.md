# ⏳ TTL 检测原理

在校园网多设备检测的各种技术手段中，**TTL 检测**是成本最低、应用最广的。

## ❓ 什么是 TTL

TTL（Time To Live） 是 IPv4 数据包首部中的一个 8 位（bit） 字段，它的主要作用是防止数据包在网络中因路由环路而无休止地循环传输。

::: info 
数据包每经过一台三层路由转发，TTL都会 -1 ，当为 0 时，路由器就会丢弃该数据包并返回错误信息
:::

### 📃 常见操作系统的默认初始 TTL 值

不同操作系统发出的数据包，其初始 TTL 设定并不完全相同：

| 操作系统类型 | 默认初始 TTL 值 | 常见网络设备 / 系统示例 |
| :--- | :--- | :--- |
| **Linux / Android** | **64** | Android 手机、OpenWrt 路由器、大部分 Linux 发行版 |
| **iOS / macOS** | **64** | iPhone、iPad、MacBook |
| **Windows** | **128** | Windows 10/11、Windows Server |
| **Unix / 部分网络设备** | **255** | Cisco 路由器、Solaris 系统等 |

## 🔬 校园网检测 TTL 的原理

校园网网关在出口处对所有 IPv4 数据包首部的 `TTL` 字段进行实时校验。

### 1. 正常直连（未挂载路由器）

当单台设备直接连接校园网时，数据包未经中间路由转发，网关接收到的 TTL 保持为系统默认初始值。

| 设备类型 | 请求流量类型 | 抓取的 TTL 特征 | 校园网网关判定 |
| :--- | :--- | :--- | :--- |
| Windows 电脑 | IPv4 数据包 | TTL = `128` | 唯一设备（Windows） |
| Android 手机 | IPv4 数据包 | TTL = `64` | 唯一设备（Android/iOS） |

---

### 2. 挂载路由器（经过路由 NAT 转发）

宿舍接入路由器后，设备的流量经过路由转发时 `TTL` 均被强制 `-1` 。

| 下挂设备组合 | 抓取的 TTL 特征 | 校园网网关判定 |
| :--- | :--- | :--- |
|  Windows 电脑 | TTL = `127` | ⚠️ **封禁或增加封禁概率** |
| Windows 电脑 + Android 手机 | TTL = `127` 与 `63` 混合出现 | ⚠️ **封禁或增加封禁概率** |
